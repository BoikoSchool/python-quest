# Python Quest

Тренажер Python для учнів 5–9 класів. Учні пишуть і запускають справжній Python просто в браузері шкільного планшета: нічого не треба встановлювати, достатньо відкрити посилання.

**Сайт:** https://boikoschool.github.io/python-quest/

- Після першого відкриття сайт працює без інтернету. Його можна додати на головний екран планшета.
- Планшети спільні, тому при вході учень обирає себе на екрані «Хто ти?» (клас → ім'я) або пише ім'я, прізвище й клас, якщо він тут уперше. Паролів немає. У кожного учня свій код і прогрес.
- Код виконується лише на пристрої. Прогрес зберігається тільки в браузері цього планшета. У «Налаштуваннях» його можна зберегти у файл і відновити на іншому планшеті.
- Учитель може отримувати результати в свою Google Таблицю: хто, коли й яку місію виконав, і з яким кодом (див. [«Результати в Google Таблиці»](#результати-в-google-таблиці-для-вчителя)). Поки це не налаштовано, нічого не залишає планшет. Інших даних не збираємо.
- Повне технічне завдання: [docs/SPEC.md](docs/SPEC.md).

## Які пристрої підходять

- iPad: Safari, **iPadOS 16.4 або новіша**. Старіші iPad з iPadOS 16.0–16.3 безкоштовно оновлюються до 16.7.
- Android-планшет: **Chrome 112 або новіший**.
- Ноутбуки й комп'ютери з сучасним Chrome, Edge, Firefox або Safari теж працюють.

Ці мінімуми задає Pyodide — Python, зібраний для браузера.

## Як влаштовано

- Звичайні HTML, CSS і JavaScript без фреймворків. Сайт не потребує збирання: GitHub Pages віддає файли з репозиторію як є.
- Python — це [Pyodide](https://pyodide.org) **314.0.7** (Python 3.14). Ядро лежить у `vendor/pyodide/`, жодних CDN:
  `pyodide.mjs`, `pyodide.asm.mjs`, `pyodide.asm.wasm`, `python_stdlib.zip`, `pyodide-lock.json`.
- Python працює в окремому потоці (`js/py-worker.js`), тож сторінка не зависає. Якщо програма учня працює довше 5 секунд, потік зупиняється й запускається новий.
- Редактор коду — [CodeMirror 6](https://codemirror.net), зібраний в один файл `vendor/codemirror.js`. «Розумні» лапки й тире, які вставляє iPad (`“ ” ‘ ’ –`), редактор сам замінює на звичайні.
- Робота без інтернету — Service Worker (`sw.js`, вмикає його `js/offline.js`). Він кладе в кеш браузера весь сайт: сторінку, скрипти, місії й Pyodide. Кешів два: сайт (≈ 0,5 МБ) і Pyodide (≈ 13 МБ). Оновлення сайту не завантажує Pyodide повторно. При першому відкритті Python стартує, щойно Service Worker почав керувати сторінкою (не пізніше ніж за 8 с), тож Pyodide завантажується один раз і відразу потрапляє в кеш.

## Робота з кодом

Потрібен [Node.js](https://nodejs.org) 18 або новіший.

```bash
npm install                              # інструменти й тести (сайту вони не потрібні)
npx serve .                              # локальний сервер, далі відкрий адресу, яку він покаже
node tools/validate-missions.mjs         # перевірка місій
npx playwright install webkit chromium   # один раз: браузери для тестів
npx playwright test                      # автотести на емуляції iPad і Android-планшета
node tools/build-icons.mjs               # лише після зміни icons/icon.svg: PNG-іконки
```

Локально `sw.js` має версію `dev`: файли сайту він бере спершу з мережі, тож правки видно після звичайного оновлення сторінки. Тестовий сервер (`tests/server.mjs`) підставляє версію `test`, як на справжньому сайті, тому тести перевіряють бойовий режим кешу.

**Перед кожним комітом** перевірка місій і тести Playwright мають бути зеленими.

На Linux браузерам для тестів можуть знадобитися системні бібліотеки: `sudo npx playwright install-deps`. На Ubuntu 26.04 зараз бракує лише `libavif16`: `sudo apt-get install libavif16`.

Тести запускають сайт за адресою `/python-quest/`, так само як на GitHub Pages (`tests/server.mjs`), тому помилки зі шляхами видно одразу. Щоб прогнати ті самі тести проти живого сайту:

```bash
PQ_BASE_URL=https://boikoschool.github.io/python-quest/ npx playwright test
```

## Результати в Google Таблиці (для вчителя)

Коли учень здає місію, тренажер надсилає в таблицю вчителя один рядок: час, учень, клас, місія, скільки разів учень натискав «Перевірити», скільки підказок відкрив, скільки хвилин минуло від першого відкриття місії, і код учня. Учень бачить «✔ Результат надіслано вчителю». Якщо інтернету немає — «Результат надішлеться, коли з'явиться інтернет»: запис чекає на планшеті й піде сам, щойно з'явиться мережа або сайт відкриють наступного разу. Повторне проходження вже виконаної місії не надсилається.

У таблиці два аркуші, обидва скрипт створює сам:

- **«Журнал»** — рядок на кожну здану місію: учень, клас, час (`27.10 13:10`), місія, перевірки, підказки, хвилини, код. Той самий учень із тим самим класом і місією вдруге не додається. Код показано в один рядок моноширинним шрифтом, тож усі рядки однакової висоти; увесь код видно в рядку формул, якщо клацнути клітинку.
- **«Зведення»** — учні × місії: ✔ і дата. Оновлюється саме після кожного нового запису.

На обох аркушах закріплені заголовок і стовпець «Учень». Меню **Python Quest → Оновити таблицю** заново оформлює «Журнал» і перебудовує «Зведення» (меню з'являється, коли таблицю відкрито заново).

**Важливо про планшети.** Профіль учня і його прогрес живуть лише на тому планшеті, де учень його створив, — між планшетами вони не синхронізуються. Сів учень за інший планшет — він створює там себе ще раз і бачить чисту карту (перенести код можна через «Налаштування → Експортувати / Імпортувати прогрес»). Натомість «Зведення» збирає виконані місії з усіх планшетів класу: учня впізнає за ім'ям і класом, тож пишіть їх однаково.

### Як підключити (один раз, ≈ 10 хвилин)

Потрібен Google-акаунт учителя (особистий або шкільний Google Workspace).

1. Створіть нову Google Таблицю (sheets.new), назвіть її, наприклад, «Python Quest — результати».
2. У таблиці: **Розширення → Apps Script**. Відкриється редактор скрипта.
3. Видаліть усе, що там є, і вставте вміст файлу [`apps-script/Code.gs`](apps-script/Code.gs) з цього репозиторію. Натисніть 💾 **Зберегти**.
4. **Розгорнути → Нове розгортання**. Біля «Виберіть тип» натисніть ⚙ і виберіть **Вебзастосунок**.
   - Опис: будь-який, наприклад «Python Quest».
   - **Виконувати як: я** (ваш акаунт).
   - **Хто має доступ: Усі** (саме «Усі», без входу в акаунт — інакше планшети не зможуть надсилати).
   - Натисніть **Розгорнути**.
5. Google попросить дозвіл: **Надати доступ** → виберіть свій акаунт → «Google не перевірив цей застосунок» → **Додатково → Перейти до … (небезпечно)** → **Дозволити**. Це ваш власний скрипт: він працює лише з цією таблицею.
6. Скопіюйте **URL вебзастосунку** — він закінчується на `/exec`.
7. Перевірка: відкрийте цей URL у браузері. Має з'явитися «Python Quest: приймач результатів працює.»
8. Впишіть URL у [`js/config.js`](js/config.js):
   ```js
   export const RESULTS_URL = 'https://script.google.com/macros/s/…/exec';
   ```
   і зробіть commit і push у `main`. Після публікації на планшетах з'явиться «Доступне оновлення» — після «Оновити» результати почнуть надходити.

Щоб вимкнути надсилання, поверніть `RESULTS_URL = ''`.

### Як застосувати нову версію `Code.gs` (URL не зміниться)

Після збереження редактор Apps Script ще не міняє робочу версію: вебзастосунок і далі виконує ту, що була розгорнута. Нову треба розгорнути в **те саме** розгортання.

1. Відкрийте таблицю → **Розширення → Apps Script**.
2. Виділіть увесь старий текст (Ctrl+A / ⌘A), вставте новий вміст [`apps-script/Code.gs`](apps-script/Code.gs) і натисніть 💾 **Зберегти**.
3. **Розгорнути → Керувати розгортаннями**.
4. Виберіть наявне розгортання (те, чий URL вписано в `js/config.js`) і натисніть ✏ **Редагувати**.
5. У полі **Версія** виберіть **Нова версія**, за бажанням допишіть опис (наприклад, «оформлення таблиці»). «Виконувати як» і «Хто має доступ» не міняйте.
6. Натисніть **Розгорнути**. URL вебзастосунку лишається тим самим, `js/config.js` і сайт міняти не треба.
7. Якщо Google знову попросить дозвіл — надайте його так само, як під час першого підключення.
8. Відкрийте таблицю заново (щоб з'явилося оновлене меню) і виберіть **Python Quest → Оновити таблицю** — так нове оформлення отримають і рядки, що вже були. Без цього вони оновляться з першим новим записом.

Не натискайте **Розгорнути → Нове розгортання**: воно створює ще одну адресу, і планшети далі надсилатимуть на стару.

Перевірка: відкрийте URL у браузері — має бути «Python Quest: приймач результатів працює.», а в **Розгорнути → Керувати розгортаннями** біля розгортання — номер нової версії.

**Версія з оформленням таблиці** переставляє стовпці «Журналу» («Учень» тепер перший). Наявні рядки вона переставить сама за назвами заголовків — нічого видаляти не треба.

**Що варто знати**

- URL записаний у публічному коді сайту. Надіслати запис може будь-хто, хто його знає, тож зрідка в «Журналі» може з'явитися зайвий рядок — його можна просто видалити (потім «Python Quest → Оновити таблицю»). Саму таблицю бачите лише ви та ті, кому ви її відкрили.
- Щоб учень міг здати місію наново (наприклад, щоб надіслати кращий код), видаліть його рядок у «Журналі». На планшеті місія все одно лишається виконаною, тож повторно вона не надішлеться — для цього учень може видалити себе в «Налаштуваннях» і створити знову.
- Старих учнів (наприклад, наприкінці року) прибирають на кожному планшеті: **Налаштування → Видалити учня з цього планшета**. Таблиці це не торкається, а записи, які ще чекали на інтернет, усе одно будуть надіслані.

## Як додати місію

Найпростіше — попросити Claude Code: `/add-mission цикли while, збір макулатури`.

Вручну:

1. Створи `missions/<id>.json`. Зразок — будь-яка наявна місія, формат описано в [docs/SPEC.md](docs/SPEC.md), розділ 4.
   - Обов'язкові поля: `id` (як назва файлу), `title`, `topic`, `task`, `starter`, `tests`, `learn`.
   - `learn` — блок «Як це працює» над завданням: коротке пояснення теми й приклад на схожій, але іншій задачі з поясненням ключових рядків (для умов, циклів і функцій — ще й про відступи). Приклад не повинен проходити тести місії.
   - Тестів щонайменше 3, і хоча б один прихований (`"hidden": true`). Додай граничні випадки: 0, від'ємні числа, порожній рядок.
   - Вхідні дані тесту: кожне значення з нового рядка (`"120\n25"`). Щоб передати один порожній рядок, пиши `"\n"`.
2. Напиши еталонний розв'язок у `missions/solutions/<id>.py`.
3. Додай `id` у потрібну тему в `missions/index.json`. Поле `topic` місії має збігатися з назвою теми.
4. Запусти `node tools/validate-missions.mjs`. Він перевірить, що розв'язок проходить усі тести, а стартовий шаблон і приклад із `learn` — ні.

### Еталонні розв'язки — лише локально

Папка `missions/solutions/` записана в `.gitignore`, і в публічний репозиторій розв'язки не потрапляють. Тому:

- **зроби резервну копію** цієї папки, наприклад у хмару: на GitHub її немає;
- у CI валідатор працює з прапорцем `--no-solutions` і перевіряє лише формат і шаблони;
- тести Playwright з еталонними розв'язками пропускаються там, де розв'язків немає.

## Як оновити Pyodide

Найпростіше — `/update-pyodide` у Claude Code. Вручну:

1. Прочитай примітки до випуску нової версії: https://pyodide.org/en/stable/project/changelog.html
2. `npm install --save-exact pyodide@<версія>`
3. `node tools/build-vendor.mjs` — скопіює нове ядро у `vendor/pyodide/`.
4. Онови номер версії в цьому README і `PYODIDE_VERSION` у `sw.js` (тест звіряє її з `package.json`).
5. Перевірка місій і `npx playwright test` мають бути зеленими.

CodeMirror оновлюється так само: зміни версії в `package.json`, `npm install`, `node tools/build-vendor.mjs`.

## Як оновити Playwright

Playwright — це лише інструмент для тестів, на сайт він не потрапляє. У CI тести йдуть в офіційному контейнері `mcr.microsoft.com/playwright`, де вже є браузери. Тому версію треба міняти у двох місцях разом:

1. `npm install --save-exact @playwright/test@<версія>` — версія в `package.json` має бути точною, без `^`.
2. У `.github/workflows/pages.yml` зміни тег контейнера на ту саму версію: `image: mcr.microsoft.com/playwright:v<версія>-noble`. Список тегів: https://mcr.microsoft.com/v2/playwright/tags/list
3. `npx playwright install webkit chromium` — нові браузери для локальних тестів.
4. `npx playwright test` має бути зеленим. Тест `tests/versions.spec.js` звіряє тег контейнера з `package.json` і впаде, якщо версії розійшлися.

## Публікація

GitHub Actions (`.github/workflows/pages.yml`):

1. **на кожен push і pull request** перевіряє місії (`--no-solutions`) і проганяє тести Playwright на емуляції iPad і Android-планшета. Тести йдуть в офіційному контейнері Playwright, де браузери вже встановлено, тож нічого не завантажується з дзеркал Ubuntu. Якщо тести впали, скриншоти й trace лежать в артефакті `playwright-results`;
2. **після push у `main`**, якщо тести зелені, публікує на GitHub Pages **лише файли сайту**: `index.html`, `manifest.webmanifest`, `sw.js`, `css/`, `js/`, `icons/`, `vendor/`, `missions/*.json`.

Під час публікації в `sw.js` підставляється версія кешу — хеш файлів сайту. Змінився сайт — і в учнів з'являється банер «Доступне оновлення». Кнопка «Оновити» зберігає код і перезавантажує сторінку. Вручну версію міняти не треба.

Додаєш до сайту новий файл чи папку — допиши їх у крок «Збираємо файли сайту» у workflow і в список `APP_FILES` у `sw.js` (тест перевіряє, що всі файли зі списку існують).

## Розмір першого завантаження

Перше відкриття сайту передає **≈ 7,0 МБ** за 55 запитів (виміряно 26.10.2026 на живому сайті в Chromium, разом із запитами Service Worker). GitHub Pages стискає файли, тож без стиснення це ≈ 14,7 МБ.

Pyodide завантажується один раз і відразу потрапляє в кеш. Двічі завантажуються лише дрібні файли сайту й місії: Service Worker кладе в кеш їхні свіжі копії (≈ 0,3 МБ зі стисненням).

| Файл | Передається | Без стиснення |
| --- | --- | --- |
| `vendor/pyodide/pyodide.asm.wasm` | 3,6 МБ | 9,6 МБ |

## Що де лежить

- `docs/SPEC.md` — повне ТЗ (етапи 1–4).
- `CLAUDE.md` — короткі правила, які Claude читає в кожній сесії.
- `.claude/rules/` — правила, що вмикаються лише для місій і для коду Pyodide.
- `.claude/skills/` — навички:
  - `/add-mission`, `/tablet-check`, `/update-pyodide` — для цього проєкту;
  - `/liquid-glass-ui` — стиль «рідке скло» з запобіжниками для слабких планшетів;
  - `/frontend-design`, `/webapp-testing`, `/skill-creator` — офіційні навички Anthropic (github.com/anthropics/skills, ліцензія Apache 2.0).
