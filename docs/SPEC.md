Версія від 27.10.2026 (додано етап 4: профілі учнів і результати для вчителя)

> Це разове завдання на етапи 1–4. Постійні правила проєкту лежать у `CLAUDE.md` і `.claude/rules/`, повторювані процедури — у `.claude/skills/`. Реалізуй поетапно (розділ 5, «Етапи»), після кожного етапу зупиняйся й показуй результат.

## 1. Мета та обмеження

Потрібен вебтренажер, у якому учні пишуть і запускають справжній Python на шкільних планшетах. Ніщо не встановлюється: учень відкриває посилання, і все працює в браузері. Перший робочий прототип — це статичний сайт на GitHub Pages із 10 місіями. Його ми далі доопрацьовуватимемо ітераціями.

**Аудиторія**

- Учні 5–9 класів (10–15 років), які починають вивчати Python. Учитель працює з класом на уроці.
- Інтерфейс, завдання та повідомлення про помилки — українською мовою.
- Тексти короткі й прості, без жаргону. Кожне завдання має життєвий сюжет.

**Цільові пристрої**

- iPad (Safari, iPadOS 16.4+) та Android-планшети (Chrome 112+) — це мінімум, на якому тестують Pyodide. Серед них є слабкі моделі з 2–3 ГБ пам'яті.
- Екранна клавіатура, з фізичною клавіатурою або без неї. Портретна й альбомна орієнтація.
- Ноутбуки й комп'ютери теж мають працювати, але планшет є головним сценарієм.

**Жорсткі обмеження**

- Нічого не встановлювати: ні Python, ні застосунки з магазину. Достатньо відкрити посилання.
- Без власного сервера та бази даних. Код учня виконується лише на пристрої.
- Без реєстрації та паролів. Прогрес зберігається тільки в браузері. Єдиний виняток — п. 3.8: якщо вчитель налаштував таблицю, запис про зараховану місію (ім'я, клас, місія, код) іде в його Google Таблицю. Інших даних не збираємо.
- Після першого завантаження сайт працює без інтернету. У школах Wi-Fi часто нестабільний.
- Хостинг — GitHub Pages: тільки статичні файли, власні HTTP-заголовки задати не можна.

**Відкриті питання** (поки що діємо за припущеннями, наведеними вище)

- Чи точно 5–9 класи, чи потрібна окрема лінійка для 10–11 класів?
- Скільки місій на старті та за якою програмою (НУШ, конкретний підручник)?
- Який ще потрібен режим учителя (набір місій за посиланням тощо)? Зараз учитель бачить результати в Google Таблиці (етап 4), решта — на етапі 5.

## 2. Архітектура

Сайт статичний, без кроку збирання. Python (Pyodide) працює в окремому Web Worker, тому інтерфейс не зависає. Service Worker кешує всі файли, і після першого відкриття сайт працює офлайн.

```
GitHub Pages (статичні файли)
        │ перше завантаження
        ▼
┌──────────────── Браузер на планшеті ────────────────┐
│  Service Worker — кешує сторінку, місії, Pyodide     │
│        │ файли з кешу                                │
│        ▼                                             │
│  Інтерфейс (головний потік)  ──код і дані──▶  Web Worker
│  редактор, місії, перевірка  ◀────вивід─────  Pyodide │
│        │ профілі, код і прогрес, черга результатів   │
│        ▼                                             │
│  localStorage                                        │
└────────┬─────────────────────────────────────────────┘
         │ POST (no-cors, text/plain) — лише зараховані місії
         │ і лише якщо в js/config.js є URL
         ▼
Google Apps Script вчителя → Google Таблиця («Журнал», «Зведення»)
```

**Технічні рішення**

1. **Стек:** чистий HTML, CSS і JavaScript (ES-модулі) без фреймворків. Сайт має відкриватися з GitHub Pages напряму, без `npm run build`. Код повинен бути зрозумілим людині, яка не є професійним програмістом.
2. **Pyodide розміщуємо на своєму сайті**, а не з CDN. У `vendor/pyodide/` кладемо лише ядро (pyodide.mjs, pyodide.asm.mjs, pyodide.asm.wasm, python_stdlib.zip, pyodide-lock.json). Обираємо актуальну стабільну версію й фіксуємо її номер у README. Так кешування простіше і немає залежності від стороннього CDN.
3. **Виконання коду — тільки в Web Worker** (`js/py-worker.js`). Головний потік надсилає `{code, stdin}` і отримує `{stdout, stderr, error, timeMs}`.
4. **Захист від нескінченних циклів.** Ліміт за замовчуванням 5 секунд. Якщо його перевищено, головний потік викликає `worker.terminate()` і створює новий worker. `interruptBuffer` не використовуємо: йому потрібен SharedArrayBuffer, а той вимагає заголовків COOP/COEP, яких GitHub Pages не дає. Учень бачить повідомлення «Програма працює надто довго — можливо, цикл не закінчується».
5. **input().** У версії 1 вхідні дані задаються заздалегідь у полі «Вхідні дані», кожне значення з нового рядка. Якщо рядків не вистачає, виводиться зрозуміле повідомлення українською. Інтерактивний input() (програма зупиняється й чекає на введення) відкладено на етап 5.
6. **Редактор: CodeMirror 6** з підсвічуванням Python. Він добре працює з дотиками та екранною клавіатурою. Збираємо його один раз скриптом `tools/build-vendor.mjs` (esbuild) у `vendor/codemirror.js` і комітимо готовий файл. Сам сайт збирання не потребує.
7. **PWA:** `manifest.webmanifest`, іконки та `sw.js` з версіонованим кешем. Сайт можна додати на головний екран планшета. При новій версії показується банер «Доступне оновлення».
   - Кешів два. Кеш застосунку (сторінка, стилі, скрипти, CodeMirror, місії) має назву з версією сайту. У репозиторії версія `dev`, а під час публікації CI підставляє хеш файлів сайту, тож забути оновити її неможливо. Кеш Pyodide має назву з версією Pyodide, тому оновлення сайту не завантажує 13 МБ ядра повторно.
   - Service Worker реєструється одразу. При першому відкритті Python стартує, щойно Service Worker почав керувати сторінкою (чекаємо не довше 8 с): файли Pyodide проходять через нього й кешуються на льоту, тож 13 МБ завантажуються один раз. На HTTP-кеш браузера покладатися не можна — великі файли він часто не зберігає.
8. **Збереження:** `localStorage`, ключі містять версію схеми: `pyquest:v1:profiles` (список учнів), `pyquest:v1:profile:<id>` (код і прогрес одного учня), `pyquest:v1:outbox` (черга результатів для вчителя). Поточний учень — у `sessionStorage`. Прогрес з часів до профілів (`pyquest:v1`) переходить до першого створеного учня. Експорт і імпорт прогресу поточного учня у файл `.json`. Імпорт об'єднує прогрес і нічого не губить: місія виконана, якщо вона виконана хоча б в одному джерелі, а код береться новіший. Виклик `navigator.storage.persist()`.
9. **Результати для вчителя:** Google Apps Script (`apps-script/Code.gs`), розгорнутий учителем як вебзастосунок з доступом «Усі». Сайт надсилає `fetch` POST з `mode: "no-cors"` і `Content-Type: text/plain` — без попереднього запиту CORS, який Apps Script не приймає. Відповідь прочитати не можна, тому дублікати відсіює сам скрипт. URL — у `js/config.js`; порожній — надсилання вимкнене.

## 3. Функції для учня

Найважливіше — щоб на планшеті було зручно набирати код. Без панелі символів і вимкненої автозаміни дитина не зможе набрати навіть `print("Привіт")`.

**3.1. Редактор під сенсорний екран**

- *(Відкладено, повернемося за потреби.)* Панель символів над клавіатурою з кнопками не менше 44×44 px: `⇥` (відступ 4 пробіли), `⇤` (зняти відступ), `( ) [ ] { } : " ' = + - * / < > # _ , .`, а також «Скасувати» та «Повторити». Кнопка вставляє символ у позицію курсора й не закриває клавіатуру.
- Вимкнено автокорекцію, автоматичну велику літеру та перевірку правопису (`autocorrect=off`, `autocapitalize=off`, `spellcheck=false`). Без цього iPad перетворює `print` на `Print`.
- Автозаміна «розумних» лапок і тире на звичайні: `“ ” ‘ ’ –` → `" " ' ' -`. iOS вставляє такі лапки за замовчуванням, і вони дають SyntaxError. Заміна працює під час набору й вставлення. Лапки-ялинки `« »` лишаються: їх пишуть у рядках українською. *(Перенесено в етап 3.)*
- Автовідступ: після `:` і Enter додається 4 пробіли, наступний рядок зберігає відступ попереднього.
- Підсвічування синтаксису, номери рядків, підсвічування рядка з помилкою.
- *(Відкладено, повернемося за потреби.)* Кнопки A− / A+ змінюють розмір шрифту від 14 до 22 px; вибраний розмір запам'ятовується.
- Код кожної місії автоматично зберігається (із затримкою 500 мс).

**3.2. Розкладка екрана**

*(Розкладки, перемикач теми й «рідке скло» відкладено, повернемося за потреби. Зараз тема світла чи темна автоматично, за налаштуванням планшета.)*

- Альбомна орієнтація: ліворуч умова місії, праворуч редактор і консоль.
- Портретна орієнтація: вкладки «Завдання», «Код» і «Результат». Після запуску автоматично відкривається «Результат».
- Кнопки «▶ Запустити» та «✓ Перевірити» видно завжди, навіть коли відкрита екранна клавіатура (використати `visualViewport`).
- Темна та світла теми, контраст тексту не нижчий за WCAG AA. Перемикач теми в налаштуваннях відкладено.
- Візуальний стиль «рідке скло» для панелей, вкладок і карток місій. Спершу CSS-версія, справжнє скло (бібліотека Glass-HQ/liquid-glass) — лише як покращення на пристроях з WebGPU. Редактор і консоль завжди без скла. Деталі й запобіжники — у навичці `liquid-glass-ui`.

**3.3. Запуск і консоль**

- Pyodide починає завантажуватися у фоні одразу після відкриття сторінки. Під час завантаження видно смугу прогресу й текст «Готуємо Python…».
- Консоль показує вивід програми, час виконання та помилки. Кнопка «Очистити».
- Поле «Вхідні дані» розгорнуте, якщо в коді є `input(`, і згорнуте в інших випадках.

**3.4. Зрозумілі помилки**

Учень бачить пояснення українською, номер рядка та оригінальне повідомлення Python дрібним шрифтом. Мінімальний словник помилок *(перенесено в етап 3)*:

| Помилка | Пояснення для учня |
| --- | --- |
| SyntaxError | У рядку N порушено правила запису. Перевір дужки, лапки та двокрапку. |
| IndentationError | Відступи не збігаються. Усередині блоку однакові відступи — 4 пробіли. |
| NameError | Python не знає імені «x». Можливо, змінна ще не створена або є одрук. |
| TypeError | Операцію виконано над несумісними типами, наприклад рядок + число. |
| ValueError | Не вдалося перетворити значення. Наприклад, `int("абв")`. |
| ZeroDivisionError | Ділення на нуль. |
| EOFError | Програма просить більше вхідних даних, ніж їх задано в полі «Вхідні дані». |
| Таймаут | Програма працює надто довго. Можливо, цикл не закінчується. |

**3.5. Пояснення теми, підказки й перевірка місії**

- Над завданням — блок «Як це працює» (поле `learn`), відкритий за замовчуванням, його можна згорнути. Згорнутий чи розгорнутий стан запам'ятовується для кожної місії окремо. Виконані місії відкриваються зі згорнутим блоком. У ньому заголовок, 2–5 речень простими словами, приклад коду на схожій, але іншій задачі й пояснення ключових рядків. Для умов, циклів і функцій — окремий абзац про відступи. Учень спершу читає й пробує приклад, а потім розв'язує місію за схожою схемою.
- Приклад можна змінювати. Кнопка «▶ Спробувати» запускає його й показує вивід під прикладом, не чіпаючи код місії. Зміни прикладу не зберігаються.

- Код запускається на кожному тесті місії. Вивід порівнюється за рядками; пробіли в кінці рядків і порожні рядки в кінці ігноруються.
- Тести бувають відкриті (учень бачить вхід, очікуваний вивід і свій вивід для першого невдалого тесту) і приховані (повідомлення лише «прихований тест не пройдено»).
- Необов'язкове запитання на розуміння. Місія зараховується, коли пройдено всі тести й дано правильну відповідь.
- Підказки — кнопка «Не виходить? Підказка» під редактором, відкриває по одній: 1, потім 2, потім 3. Готового розв'язку у версії 1 немає.
- Після зарахування — кнопка «Наступна місія». *(Відкладено, повернемося за потреби: анімація та зірки — 3 без підказок, 2 з однією, 1 з більшою кількістю.)*

**3.6. Прогрес і навігація**

- Карта місій, розбитих за темами, зі статусами «не почато», «в роботі» та «виконано». Кількість зірок — відкладено.
- «Пісочниця» — вільний редактор без завдання.
- Налаштування (для поточного учня): «Експортувати прогрес», «Імпортувати прогрес» (об'єднує з наявним прогресом, після підтвердження), «Скинути все» (з підтвердженням). «Видалити учня з цього планшета» — див. п. 3.7. Розмір шрифту й тему відкладено, повернемося за потреби.

**3.7. Профілі учнів** *(етап 4; раніше були в етапі «Розвиток»)*

Шкільні планшети спільні, на одному може бути до ~150 учнів.

- При вході — екран «Хто ти?»: спершу кнопки класів, які є на цьому планшеті (5-А, 5-Б, …, 10-А), потім учні вибраного класу за абеткою. «Я тут уперше» — на обох кроках: форма «Ім'я та прізвище» і «Клас» (на другому кроці клас уже підставлено). Якщо учнів ще немає — одразу форма. Без паролів.
- Ім'я — щонайменше два слова, перші літери великі. Клас — будь-який текст до 30 символів, як його звикли писати в школі: `6`, `9 Харків`, `6-А`. Лише короткий запис `6а`, `6 А`, `6-а` стає `6-А`, щоб той самий клас не роздвоювався. Класи впорядковуються з урахуванням чисел (5-Б, 6, 9 Харків, 10-А). Такий самий учень того ж класу не створюється вдруге — його просто обирають.
- У кожного учня свій код, прогрес, стан підказок і блоків «Як це працює».
- Поточного учня пам'ятає вкладка: оновлення сторінки не питає знову, нове відкриття сайту — питає. Кнопка «Змінити учня» у верхній панелі поруч з ім'ям і класом.
- Прогрес, що був на планшеті до профілів, отримує перший створений учень.
- Налаштування → «Видалити учня з цього планшета»: список учнів, підтвердження, видаляється профіль і його прогрес. Черга результатів для вчителя не змінюється. Видалив себе — знову «Хто ти?».
- Між планшетами прогрес не синхронізується (перенесення — експорт/імпорт файлу).

**3.8. Результати для вчителя** *(етап 4; раніше були в етапі «Розвиток»)*

- Коли місію зараховано вперше, сайт надсилає запис: час, учень, клас, id і назва місії, кількість натискань «Перевірити», кількість відкритих підказок, хвилини від першого відкриття місії, код учня. Повторне проходження виконаної місії не надсилається.
- Запис спершу потрапляє в чергу на планшеті й відправляється одразу; якщо не вдалося — сам при появі мережі, раз на 2 хвилини, поки сайт відкритий, або під час наступного відкриття сайту.
- Учень бачить лише «✔ Результат надіслано вчителю» або «Результат надішлеться, коли з'явиться інтернет». Якщо надсилання ввімкнене, на «Хто ти?» і на карті сказано, що зараховані місії бачить учитель.
- `apps-script/Code.gs`: аркуш «Журнал» — рядок на запис, заголовки створюються самі, текст, що починається з `= + - @`, записується як текст, `LockService` для одночасних запитів; той самий учень + клас + місія вдруге не додається. Аркуш «Зведення» — учні × місії з ✔ і датою, скрипт перебудовує його сам. Оформлення: час `27.10 13:10`, код моноширинним шрифтом без перенесення (рядки однакової висоти), закріплені заголовок і стовпець «Учень»; меню «Python Quest → Оновити таблицю».
- Покрокова інструкція для вчителя — у README.

## 4. Місії

Кожна місія — окремий JSON-файл у `missions/`. Учитель може додати нове завдання, не торкаючись коду. Порядок і групування за темами задає `missions/index.json`. Детальні правила — у `.claude/rules/missions.md`, процедура додавання — навичка `/add-mission`.

**Формат файлу місії**

```json
{
  "id": "eco-grams",
  "title": "Екомоніторинг",
  "topic": "Введення і виведення",
  "level": 1,
  "story": "Еко-команда зважила пластик у кілограмах. Для звіту потрібні грами.",
  "task": "Прочитай ціле число — масу в кг — і виведи масу в грамах.",
  "learn": {
    "title": "Як прочитати число",
    "text": "input() читає значення з поля «Вхідні дані». Але input() завжди повертає текст, навіть якщо ввели цифри. Щоб із числом можна було рахувати, обгортаємо його в int().",
    "code": "minutes = int(input())\nseconds = minutes * 60\nprint(seconds)\n",
    "input": "2",
    "lines": [
      { "code": "minutes = int(input())", "text": "Читає рядок і робить із нього ціле число." },
      { "code": "seconds = minutes * 60", "text": "У хвилині 60 секунд, тому множимо на 60." }
    ]
  },
  "example": { "input": "3", "output": "3000" },
  "starter": "kg = int(input())\n# обчисли та виведи грами\n",
  "tests": [
    { "input": "3", "output": "3000" },
    { "input": "0", "output": "0" },
    { "input": "12", "output": "12000", "hidden": true }
  ],
  "hints": [
    "1 кг = 1000 г",
    "Помнож kg на 1000",
    "Не забудь print(...)"
  ],
  "question": {
    "text": "Навіщо int() навколо input()?",
    "options": ["input() повертає рядок", "Щоб число стало дробовим", "Без нього print() не працює"],
    "answer": 0
  },
  "skills": ["input()", "int()", "print()"],
  "timeLimitMs": 5000
}
```

Обов'язкові поля: `id`, `title`, `topic`, `task`, `starter`, `tests` (мінімум 3, з них хоча б один прихований) і `learn`. Решта полів необов'язкова.

Поле `learn` — пояснення теми (п. 3.5):
- `title` — заголовок; `text` — 2–5 речень простими словами для 10–15 років;
- `code` — приклад на схожій, але іншій задачі; `input` — вхідні дані для нього (обов'язкові, якщо приклад читає `input()`);
- `lines` — пояснення ключових рядків: `{ "code": "рядок із прикладу", "text": "що він робить" }`;
- `indent` — пояснення відступів; обов'язкове, якщо в прикладі є блок (рядок із «:»): умови, цикли, функції.

Скрипт `tools/validate-missions.mjs` перевіряє місії. Локально — формат, еталонні розв'язки з `missions/solutions/` і те, що стартовий шаблон не проходить тести. У CI (розв'язків там немає) — формат і шаблони. І там, і там приклад із `learn` має запускатися без помилок і НЕ проходити тести місії, щоб він не був готовим розв'язком.

**Стартовий набір: 10 місій**

Сюжети — шкільне життя, екологія, спорт, космос. Кожна місія має 3–5 тестів, зокрема граничні випадки.

| № | Тема | Сюжет | Що робить учень |
| --- | --- | --- | --- |
| 1 | print() | Привітання для шкільного радіо | Виводить два задані рядки |
| 2 | Змінні та арифметика | Ціна екскурсії | Рахує загальну суму для класу |
| 3 | input() та int() | Екомоніторинг | Переводить кілограми в грами |
| 4 | if / else | Допуск на атракціон | Порівнює зріст із межею |
| 5 | if / elif / else | Метеостанція | Виводить МОРОЗ, НУЛЬ або ТЕПЛО |
| 6 | for і range() | Космічний відлік | Виводить відлік від N до 1 і «Старт!» |
| 7 | while | Скарбничка | Рахує тижні, поки накопичиться потрібна сума |
| 8 | Рядки | Шифр розвідника | Виводить слово навпаки та його довжину |
| 9 | Списки | Шкільна олімпіада | Знаходить найкращий бал і середнє |
| 10 | Функції | Квиткова каса | Пише функцію знижки й викликає її |

## 5. Якість, пастки, приймання та етапи

**Відомі пастки (обов'язково врахувати)**

- **Promise замість результату.** В оригінальному сайті-прикладі через `runPythonAsync(...).toJs()` не працювала жодна кнопка. Спочатку `await`, потім робота з результатом; PyProxy звільнити через `.destroy()`.
- **Безпечне виконання.** Кожен запуск отримує новий словник змінних. `sys.stdout` і `input` відновлюються в блоці `finally`. Помилка в коді учня не повинна ламати worker.
- **Пам'ять слабких планшетів.** Pyodide завантажується один раз на worker. Усі тести місії проганяються одним повідомленням до worker, а не перезавантаженням.
- **Safari може стерти localStorage** приблизно після 7 днів без відвідувань, якщо сайт не додано на головний екран. Потрібні підказка «Додай на головний екран», `storage.persist()` та експорт прогресу у файл.
- **Шляхи на GitHub Pages.** Сайт живе в підпапці `/<назва-репозиторію>/`, тому використовуємо тільки відносні шляхи, у Service Worker теж.
- **Розумні лапки та автозаміна** на iOS — див. п. 3.1.

**Нефункціональні вимоги**

- Повторне відкриття (файли в кеші): інтерфейс за 1 секунду, Python готовий за 5 секунд на планшеті середнього рівня.
- Розмір першого завантаження виміряти й зазначити в README.
- Доступність: усі кнопки мають підписи (`aria-label`), консоль оголошується через `aria-live`, працює керування з клавіатури.
- Жодних зовнішніх запитів після першого завантаження: ні аналітики, ні шрифтів з CDN. Єдиний виняток — POST результатів на URL з `js/config.js` (п. 3.8).
- Автотести Playwright на емуляції iPad (WebKit) і Android-планшета (Chromium): запуск коду, таймаут циклу, перевірка місії, офлайн-режим, збереження прогресу після перезавантаження.
- GitHub Actions: валідація місій і Playwright на кожен push.

**Критерії приймання версії 1**

- [ ] На iPad у Safari учень відкриває посилання, набирає `print("Привіт")` і бачить результат. Поки код набирають з екранної клавіатури: панель символів відкладено, а «розумні» лапки замінюються самі.
- [ ] `while True: pass` зупиняється через 5 секунд із зрозумілим повідомленням, після чого наступний запуск працює.
- [ ] Усі 10 місій зараховуються еталонними розв'язками й не зараховуються порожнім шаблоном.
- [ ] Після першого відкриття в режимі «в літаку» сайт відкривається й виконує код.
- [ ] Прогрес зберігається після закриття вкладки; експорт і імпорт файлу відновлюють його на іншому пристрої.
- [ ] Кожна помилка зі словника п. 3.4 показується українською з номером рядка.
- [ ] Playwright-тести зелені в CI.

**Критерії приймання етапу 4**

- [ ] Двоє учнів на одному планшеті мають окремий код і прогрес; «Змінити учня» повертає на «Хто ти?».
- [ ] Серед 150 учнів учень знаходить себе за два дотики: клас → ім'я.
- [ ] Старий прогрес планшета переходить до першого учня; видалення учня прибирає лише його дані.
- [ ] Зарахована місія з'являється в «Журналі» й «Зведенні» таблиці вчителя; повторне проходження і повторна відправка не дають дубліката.

- [ ] З порожнім `js/config.js` сайт не робить жодного зовнішнього запиту.

**Етапи** (після кожного — демонстрація й зворотний зв'язок)

1. **Ядро.** Worker із Pyodide, runner з таймаутом, редактор, 3 місії, перевірка, деплой на GitHub Pages.
2. **Планшет — відкладено, повернемося за потреби.** Панель символів, розкладки для портретної та альбомної орієнтації, розмір шрифту й перемикач теми, зірки, стиль «рідке скло» (CSS-версія + скло на пристроях з WebGPU). Вимкнення автокорекції зроблено на етапі 1. Автозаміну лапок, словник помилок і підказки перенесено в етап 3.
3. **Офлайн і контент.** PWA, усі 10 місій, валідатор, експорт та імпорт, Playwright і CI. З етапу 2: автозаміна «розумних» лапок і тире, словник помилок, підказки по одній (без зірок). Блок «Як це працює» з поясненням теми й прикладом для кожної місії.
4. **Профілі й результати для вчителя.** Профілі учнів на спільному планшеті (п. 3.7) і надсилання зарахованих місій у Google Таблицю вчителя з офлайн-чергою (п. 3.8). Перенесено з етапу «Розвиток».
5. **Розвиток (окреме ТЗ пізніше).** Режим учителя (набір місій за посиланням, звіт учня у файл), інтерактивний input(), графіка turtle, нові теми. *(Профілі учнів і результати для вчителя перенесено в етап 4.)*
