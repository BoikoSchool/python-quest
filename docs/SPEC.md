# ТЗ: Python-тренажер для планшетів

Версія від 20.10.2026

> Це разове завдання на етапи 1–3. Постійні правила проєкту лежать у `CLAUDE.md` і `.claude/rules/`, повторювані процедури — у `.claude/skills/`. Реалізуй поетапно (розділ 5, «Етапи»), після кожного етапу зупиняйся й показуй результат.

## 1. Мета та обмеження

Потрібен вебтренажер, у якому учні пишуть і запускають справжній Python на шкільних планшетах. Ніщо не встановлюється: учень відкриває посилання, і все працює в браузері. Перший робочий прототип — це статичний сайт на GitHub Pages із 10 місіями. Його ми далі доопрацьовуватимемо ітераціями.

**Аудиторія**

- Учні 5–9 класів (10–15 років), які починають вивчати Python. Учитель працює з класом на уроці.
- Інтерфейс, завдання та повідомлення про помилки — українською мовою.
- Тексти короткі й прості, без жаргону. Кожне завдання має життєвий сюжет.

**Цільові пристрої**

- iPad (Safari, iPadOS 16.4+) та Android-планшети (Chrome 112+) — це мінімум, на якому тестують Pyodide. Серед них є слабкі моделі з 2–3 ГБ пам'яті.
- Екранна клавіатура, з фізичною клавіатурою або без неї. Портретна й альбомна орієнтація.
- Ноутбуки й комп'ютери теж мають працювати, але планшет є головним сценарієм.

**Жорсткі обмеження**

- Нічого не встановлювати: ні Python, ні застосунки з магазину. Достатньо відкрити посилання.
- Без сервера та бази даних. Код учня виконується лише на пристрої й нікуди не надсилається.
- Без реєстрації та збору персональних даних. Прогрес зберігається тільки в браузері.
- Після першого завантаження сайт працює без інтернету. У школах Wi-Fi часто нестабільний.
- Хостинг — GitHub Pages: тільки статичні файли, власні HTTP-заголовки задати не можна.

**Відкриті питання** (поки що діємо за припущеннями, наведеними вище)

- Чи точно 5–9 класи, чи потрібна окрема лінійка для 10–11 класів?
- Скільки місій на старті та за якою програмою (НУШ, конкретний підручник)?
- Чи потрібен режим учителя вже в першій версії? Зараз він запланований на етап 4.

## 2. Архітектура

Сайт статичний, без кроку збирання. Python (Pyodide) працює в окремому Web Worker, тому інтерфейс не зависає. Service Worker кешує всі файли, і після першого відкриття сайт працює офлайн.

```
GitHub Pages (статичні файли)
        │ перше завантаження
        ▼
┌──────────────── Браузер на планшеті ────────────────┐
│  Service Worker — кешує сторінку, місії, Pyodide     │
│        │ файли з кешу                                │
│        ▼                                             │
│  Інтерфейс (головний потік)  ──код і дані──▶  Web Worker
│  редактор, місії, перевірка  ◀────вивід─────  Pyodide │
│        │ код і прогрес                               │
│        ▼                                             │
│  localStorage                                        │
└──────────────────────────────────────────────────────┘
```

**Технічні рішення**

1. **Стек:** чистий HTML, CSS і JavaScript (ES-модулі) без фреймворків. Сайт має відкриватися з GitHub Pages напряму, без `npm run build`. Код повинен бути зрозумілим людині, яка не є професійним програмістом.
2. **Pyodide розміщуємо на своєму сайті**, а не з CDN. У `vendor/pyodide/` кладемо лише ядро (pyodide.mjs, pyodide.asm.mjs, pyodide.asm.wasm, python_stdlib.zip, pyodide-lock.json). Обираємо актуальну стабільну версію й фіксуємо її номер у README. Так кешування простіше і немає залежності від стороннього CDN.
3. **Виконання коду — тільки в Web Worker** (`js/py-worker.js`). Головний потік надсилає `{code, stdin}` і отримує `{stdout, stderr, error, timeMs}`.
4. **Захист від нескінченних циклів.** Ліміт за замовчуванням 5 секунд. Якщо його перевищено, головний потік викликає `worker.terminate()` і створює новий worker. `interruptBuffer` не використовуємо: йому потрібен SharedArrayBuffer, а той вимагає заголовків COOP/COEP, яких GitHub Pages не дає. Учень бачить повідомлення «Програма працює надто довго — можливо, цикл не закінчується».
5. **input().** У версії 1 вхідні дані задаються заздалегідь у полі «Вхідні дані», кожне значення з нового рядка. Якщо рядків не вистачає, виводиться зрозуміле повідомлення українською. Інтерактивний input() (програма зупиняється й чекає на введення) відкладено на етап 4.
6. **Редактор: CodeMirror 6** з підсвічуванням Python. Він добре працює з дотиками та екранною клавіатурою. Збираємо його один раз скриптом `tools/build-vendor.mjs` (esbuild) у `vendor/codemirror.js` і комітимо готовий файл. Сам сайт збирання не потребує.
7. **PWA:** `manifest.webmanifest`, іконки та `sw.js` з версіонованим кешем. Сайт можна додати на головний екран планшета. При новій версії показується банер «Доступне оновлення».
8. **Збереження:** `localStorage` з ключем, що містить версію схеми (`pyquest:v1`). Експорт і імпорт прогресу у файл `.json`. Виклик `navigator.storage.persist()`.

**Структура файлів**

```
index.html
manifest.webmanifest
sw.js
css/app.css
js/app.js          — ініціалізація, маршрутизація між місіями

js/py-worker.js    — завантаження Pyodide і виконання коду

```

## 3. Функції для учня

Найважливіше — щоб на планшеті було зручно набирати код. Без панелі символів і вимкненої автозаміни дитина не зможе набрати навіть `print("Привіт")`.

**3.1. Редактор під сенсорний екран**

- Панель символів над клавіатурою з кнопками не менше 44×44 px: `⇥` (відступ 4 пробіли), `⇤` (зняти відступ), `( ) [ ] { } : " ' = + - * / < > # _ , .`, а також «Скасувати» та «Повторити». Кнопка вставляє символ у позицію курсора й не закриває клавіатуру.
- Вимкнено автокорекцію, автоматичну велику літеру та перевірку правопису (`autocorrect=off`, `autocapitalize=off`, `spellcheck=false`). Без цього iPad перетворює `print` на `Print`.
- Автозаміна «розумних» лапок і тире на звичайні: `“ ” ‘ ’ –` → `" " ' ' -`. iOS вставляє такі лапки за замовчуванням, і вони дають SyntaxError.
- Автовідступ: після `:` і Enter додається 4 пробіли, наступний рядок зберігає відступ попереднього.
- Підсвічування синтаксису, номери рядків, підсвічування рядка з помилкою.
- Кнопки A− / A+ змінюють розмір шрифту від 14 до 22 px; вибраний розмір запам'ятовується.
- Код кожної місії автоматично зберігається (із затримкою 500 мс).

**3.2. Розкладка екрана**

- Альбомна орієнтація: ліворуч умова місії, праворуч редактор і консоль.
- Портретна орієнтація: вкладки «Завдання», «Код» і «Результат». Після запуску автоматично відкривається «Результат».
- Кнопки «▶ Запустити» та «✓ Перевірити» видно завжди, навіть коли відкрита екранна клавіатура (використати `visualViewport`).
- Темна та світла теми, контраст тексту не нижчий за WCAG AA.
- Візуальний стиль «рідке скло» для панелей, вкладок і карток місій. Спершу CSS-версія, справжнє скло (бібліотека Glass-HQ/liquid-glass) — лише як покращення на пристроях з WebGPU. Редактор і консоль завжди без скла. Деталі й запобіжники — у навичці `liquid-glass-ui`.

**3.3. Запуск і консоль**

- Pyodide починає завантажуватися у фоні одразу після відкриття сторінки. Під час завантаження видно смугу прогресу й текст «Готуємо Python…».
- Консоль показує вивід програми, час виконання та помилки. Кнопка «Очистити».
- Поле «Вхідні дані» розгорнуте, якщо в коді є `input(`, і згорнуте в інших випадках.

**3.4. Зрозумілі помилки**

Учень бачить пояснення українською, номер рядка та оригінальне повідомлення Python дрібним шрифтом. Мінімальний словник помилок:

| Помилка | Пояснення для учня |
| --- | --- |
| SyntaxError | У рядку N порушено правила запису. Перевір дужки, лапки та двокрапку. |
| IndentationError | Відступи не збігаються. Усередині блоку однакові відступи — 4 пробіли. |
| NameError | Python не знає імені «x». Можливо, змінна ще не створена або є одрук. |
| TypeError | Операцію виконано над несумісними типами, наприклад рядок + число. |
| ValueError | Не вдалося перетворити значення. Наприклад, `int("абв")`. |
| ZeroDivisionError | Ділення на нуль. |
| EOFError | Програма просить більше вхідних даних, ніж їх задано в полі «Вхідні дані». |
| Таймаут | Програма працює надто довго. Можливо, цикл не закінчується. |

**3.5. Перевірка місії**

- Код запускається на кожному тесті місії. Вивід порівнюється за рядками; пробіли в кінці рядків і порожні рядки в кінці ігноруються.
- Тести бувають відкриті (учень бачить вхід, очікуваний вивід і свій вивід для першого невдалого тесту) і приховані (повідомлення лише «прихований тест не пройдено»).
- Необов'язкове запитання на розуміння. Місія зараховується, коли пройдено всі тести й дано правильну відповідь.
- Підказки відкриваються поступово: 1, потім 2, потім 3. Готового розв'язку у версії 1 немає.
- Після зарахування — анімація, зірки (3 без підказок, 2 з однією, 1 з більшою кількістю) і кнопка «Наступна місія».

**3.6. Прогрес і навігація**

- Карта місій, розбитих за темами, зі статусами «не почато», «в роботі» та «виконано» і кількістю зірок.
- «Пісочниця» — вільний редактор без завдання.
- Налаштування: розмір шрифту, тема, «Експортувати прогрес», «Імпортувати прогрес», «Скинути все» (з підтвердженням).

## 4. Місії

Кожна місія — окремий JSON-файл у `missions/`. Учитель може додати нове завдання, не торкаючись коду. Порядок і групування за темами задає `missions/index.json`. Детальні правила — у `.claude/rules/missions.md`, процедура додавання — навичка `/add-mission`.

**Формат файлу місії**

```json
{
  "id": "eco-grams",
  "title": "Екомоніторинг",
  "topic": "Введення і виведення",
  "level": 1,
  "story": "Еко-команда зважила пластик у кілограмах. Для звіту потрібні грами.",
  "task": "Прочитай ціле число — масу в кг — і виведи масу в грамах.",
  "example": { "input": "3", "output": "3000" },
  "starter": "kg = int(input())\n# обчисли та виведи грами\n",
  "tests": [
    { "input": "3", "output": "3000" },
    { "input": "0", "output": "0" },
    { "input": "12", "output": "12000", "hidden": true }
  ],
  "hints": [
    "1 кг = 1000 г",
    "Помнож kg на 1000",
    "Не забудь print(...)"
  ],
  "question": {
    "text": "Навіщо int() навколо input()?",
    "options": ["input() повертає рядок", "Щоб число стало дробовим", "Без нього print() не працює"],
    "answer": 0
  },
  "skills": ["input()", "int()", "print()"],
  "timeLimitMs": 5000
}
```

Обов'язкові поля: `id`, `title`, `topic`, `task`, `starter` і `tests` (мінімум 3, з них хоча б один прихований). Решта полів необов'язкова. Скрипт `tools/validate-missions.mjs` перевіряє місії: локально — формат, еталонні розв'язки з `missions/solutions/` і те, що стартовий шаблон не проходить тести; у CI (розв'язків там немає) — формат і шаблони.

**Стартовий набір: 10 місій**

Сюжети — шкільне життя, екологія, спорт, космос. Кожна місія має 3–5 тестів, зокрема граничні випадки.

| № | Тема | Сюжет | Що робить учень |
| --- | --- | --- | --- |
| 1 | print() | Привітання для шкільного радіо | Виводить два задані рядки |
| 2 | Змінні та арифметика | Ціна екскурсії | Рахує загальну суму для класу |
| 3 | input() та int() | Екомоніторинг | Переводить кілограми в грами |
| 4 | if / else | Допуск на атракціон | Порівнює зріст із межею |
| 5 | if / elif / else | Метеостанція | Виводить МОРОЗ, НУЛЬ або ТЕПЛО |
| 6 | for і range() | Космічний відлік | Виводить відлік від N до 1 і «Старт!» |
| 7 | while | Скарбничка | Рахує тижні, поки накопичиться потрібна сума |
| 8 | Рядки | Шифр розвідника | Виводить слово навпаки та його довжину |
| 9 | Списки | Шкільна олімпіада | Знаходить найкращий бал і середнє |
| 10 | Функції | Квиткова каса | Пише функцію знижки й викликає її |

## 5. Якість, пастки, приймання та етапи

**Відомі пастки (обов'язково врахувати)**

- **Promise замість результату.** В оригінальному сайті-прикладі через `runPythonAsync(...).toJs()` не працювала жодна кнопка. Спочатку `await`, потім робота з результатом; PyProxy звільнити через `.destroy()`.
- **Безпечне виконання.** Кожен запуск отримує новий словник змінних. `sys.stdout` і `input` відновлюються в блоці `finally`. Помилка в коді учня не повинна ламати worker.
- **Пам'ять слабких планшетів.** Pyodide завантажується один раз на worker. Усі тести місії проганяються одним повідомленням до worker, а не перезавантаженням.
- **Safari може стерти localStorage** приблизно після 7 днів без відвідувань, якщо сайт не додано на головний екран. Потрібні підказка «Додай на головний екран», `storage.persist()` та експорт прогресу у файл.
- **Шляхи на GitHub Pages.** Сайт живе в підпапці `/<назва-репозиторію>/`, тому використовуємо тільки відносні шляхи, у Service Worker теж.
- **Розумні лапки та автозаміна** на iOS — див. п. 3.1.

**Нефункціональні вимоги**

- Повторне відкриття (файли в кеші): інтерфейс за 1 секунду, Python готовий за 5 секунд на планшеті середнього рівня.
- Розмір першого завантаження виміряти й зазначити в README.
- Доступність: усі кнопки мають підписи (`aria-label`), консоль оголошується через `aria-live`, працює керування з клавіатури.
- Жодних зовнішніх запитів після першого завантаження: ні аналітики, ні шрифтів з CDN.
- Автотести Playwright на емуляції iPad (WebKit) і Android-планшета (Chromium): запуск коду, таймаут циклу, перевірка місії, офлайн-режим, збереження прогресу після перезавантаження.
- GitHub Actions: валідація місій і Playwright на кожен push.

**Критерії приймання версії 1**

- [ ] На iPad у Safari учень відкриває посилання, набирає `print("Привіт")` за допомогою панелі символів і бачить результат.
- [ ] `while True: pass` зупиняється через 5 секунд із зрозумілим повідомленням, після чого наступний запуск працює.
- [ ] Усі 10 місій зараховуються еталонними розв'язками й не зараховуються порожнім шаблоном.
- [ ] Після першого відкриття в режимі «в літаку» сайт відкривається й виконує код.
- [ ] Прогрес зберігається після закриття вкладки; експорт і імпорт файлу відновлюють його на іншому пристрої.
- [ ] Кожна помилка зі словника п. 3.4 показується українською з номером рядка.
- [ ] Playwright-тести зелені в CI.

**Етапи** (після кожного — демонстрація й зворотний зв'язок)

1. **Ядро.** Worker із Pyodide, runner з таймаутом, редактор, 3 місії, перевірка, деплой на GitHub Pages.
2. **Планшет.** Панель символів, вимкнення автозаміни, розкладки для портретної та альбомної орієнтації, словник помилок, підказки й зірки, стиль «рідке скло» (CSS-версія + скло на пристроях з WebGPU).
3. **Офлайн і контент.** PWA, усі 10 місій, валідатор, експорт та імпорт, Playwright і CI.
4. **Розвиток (окреме ТЗ пізніше).** Режим учителя (набір місій за посиланням, звіт учня у файл), інтерактивний input(), графіка turtle, нові теми.
